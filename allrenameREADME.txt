写真自動リネーム＆一括整理ツール (Photo Auto-Rename Tool)
取扱説明書 / README.txt
======================================================================

本書は「写真自動リネーム＆一括整理ツール」の機能、仕様、操作方法、および取り扱い上の注意点を説明するマニュアルです。


----------------------------------------------------------------------
1. 概要（Overview）
----------------------------------------------------------------------
■ ツールの目的
発掘調査、建築現場、学術調査、商品撮影、イベント取材等で大量に撮影されたデジタル写真（JPEGおよび各種RAWデータ）に対し、統一された命名規則に基づく一括リネームとローカル整理を効率的に実行するための単一HTML型Webアプリケーションです。

■ 解決する課題
・カメラ本来の連番ファイル名（例: IMG_0001.JPG）から、調査地名・トレンチ名・区画番号・撮影日付・整理番号等を含む規則的なファイル名への手動変更にかかる膨大な作業時間とヒューマンエラーの削減。
・一眼レフやミラーレスカメラ撮影時に発生する「RAW+JPG」ペアファイルの解体や個別リネーム作業の煩雑さの解消。
・クラウドサーバーにデータを送信できない機密写真や個人情報を含む現場画像に対し、セキュリティ規定を満たした完全ローカル処理環境の提供。

■ 開発背景・特徴
・完全ローカル・オフライン動作（Local Security Design）：ブラウザ内部のデータベース（IndexedDB）およびメモリ上でのみ処理を行うため、インターネット環境がない現場作業でも安心してご利用いただけます。
・RAW+JPG自動グループ化機能：同名のRAWファイルとJPEGファイルを自動判定し、1セットのメタデータおよび共通リネーム規則で統合管理します。
・多言語インターフェース対応（i18n）：日本語、英語、中国語（簡体字）、韓国語、フランス語、スペイン語の全6言語に対応。国籍を問わず共同作業現場で即座に展開可能です。


----------------------------------------------------------------------
2. 主な機能（Features）
----------------------------------------------------------------------
1. 柔軟なメタデータ設定＆命名規則プレビュー
   - 「名前1（例: 遺跡名・プロジェクト名）」、「名前2（例: TR名・現場区画）」、「名前3（例: グリッド・詳細）」、「撮影日付」、「開始連番（自動3桁ゼロパディング）」を任意に組み合わせて命名規則（ベースネーム）を決定。
   - チェックボックスによる項目の有効／無効の切り替えと、リアルタイムなリネームプレビューの確認機能。

2. ドラッグ＆ドロップによる一括読み込み＆RAW+JPGペア自動識別
   - 複数画像の一括読み込みに対応。
   - 拡張子を除く同一ベースネームを持つファイル群（例: `IMG_0001.JPG` と `IMG_0001.CR2`）を同一グループとして自動統合。

3. 高速サムネイル生成＆IndexedDBによるローカル永続保存
   - ブラウザのCanvas機能を用いた軽量サムネイルの自動生成（RAWファイル画像の場合は専用バッジによる視覚化表示）。
   - ブラウザを閉じた場合でも作業状態を維持するIndexedDB（`FlexiblePhotoDB_v2`）ストレージ設計。

4. 個別リネーム調整＆アルバム管理
   - 自動リネームされた一覧に対して、カード形式でのプレビュー表示と個別ファイル名の手動修正機能。
   - 不要な写真の個別削除、および全データの一括クリア機能。

5. JSZipによる一括ZIPアーカイブ生成・エクスポート
   - リネーム適用済みのオリジナル画像・RAWファイルを保持したまま、一元化したZIPファイルとして一括ダウンロード保存。
   - 同一名称が重複した際の「_1」、「_2」形式による競合回避処理を自動実行。

3. 動作環境（Prerequisites）
----------------------------------------------------------------------
■ 対応OS
  - Windows 10 / 11
  - macOS
  - Linux
  - ChromeOS、iPadOS、Android等の標準Webブラウザ搭載環境

■ 実行環境（Webブラウザ）
  以下のHTML5/ES6およびIndexedDBに対応したモダンWebブラウザの最新版を推奨します。
  - Google Chrome
  - Microsoft Edge
  - Mozilla Firefox
  - Apple Safari

■ プログラミング言語・必須ライブラリ
  - 特別なプログラミング言語環境（Python, Node.js等）のインストールは一切不要です。
  - 外部CDN依存（※インターネット接続時に初期描画用のスタイリングとZipライブラリをロード）:
    * Tailwind CSS (スタイル描画)
    * JSZip v3.10.1 (ブラウザ内ZIP圧縮処理)
  - オフライン環境での完全利用時は、上記ライブラリをローカル配置することでスタンドアロン動作が可能です。

4. セットアップ・インストール手順（Installation）
----------------------------------------------------------------------
1. 配布された `index.html`（または該当するHTMLファイル）をPCのローカルストレージ（例: デスクトップ、作業フォルダ）に保存します。
2. 保存した `.html` ファイルをダブルクリック、または起動中の対応Webブラウザに直接ドラッグ＆ドロップして開いてください。
3. アプリケーションが起動し、メタデータ設定画面が表示されたらセットアップ完了です。

5. 使い方（Usage）
----------------------------------------------------------------------
【基本操作フロー】

ステップ 1: 表示言語の選択
  ・画面右上の言語ドロップダウン（`日本語`, `English`, `中文`, `한국어`, `Français`, `Español`）から使用言語を選択します。

ステップ 2: メタデータ（命名規則）の設定
  ・「1. メタデータ設定」パネルにて、リネームに使用する各項目を入力・調整します。
    - 名前1〜3: 任意の文字列を入力（例: `A遺跡`_`TR1`_`D4`）
    - 日付: カレンダーから日付を選択（出力時ハイフン除去 `YYYYMMDD` 形式）
    - 開始番号: 連番のスタート数値（例: `1` → `001`）
    - 必要のない項目は左側のチェックボックスをオフにすることで非表示・省略可能。
  - 下部の「プレビュー形式」で生成されるファイル名の文字パターンを確認します。

ステップ 3: 写真ファイルのドロップ＆自動リネーム
  ・「2. 写真追加・自動リネーム」領域（破線内）に、カメラから取り込んだ写真ファイルを一括ドラッグ＆ドロップします（またはクリックしてダイアログより選択）。
  ・指定されたメタデータ規則に従い、自動的に連番が付番され、IndexedDBへと保存されます。

ステップ 4: 成果物の確認・個別修正
  ・「3. ローカルアルバム確認」パネルに読み込まれた写真一覧がカード表示されます。
  ・入力フォーム上でファイル名を個別微調整できます。
  ・不要な画像がある場合は、サムネイルホバー時に表示されるゴミ箱アイコンで個別削除が可能です。

ステップ 5: ZIPファイルの一括ダウンロード
  ・「4. バックアップとエクスポート」パネルの「ZIPで一括ダウンロード」ボタンをクリックします。
  ・ブラウザ内で圧縮処理が実行され、リネーム済みの写真一式が格納された `.zip` ファイルがダウンロードされます。

6. 入力データの仕様（Input Data Format）
----------------------------------------------------------------------
■ 対応ファイル形式
  - 標準画像フォーマット: JPEG (`.jpg`, `.jpeg`), PNG (`.png`), WebP (`.webp`), GIF (`.gif`), BMP (`.bmp`)
  - RAW画像フォーマット: Canon (`.cr2`, `.cr3`), Nikon (`.nef`), Sony (`.arw`), Fujifilm (`.raf`), Olympus (`.orf`), Panasonic (`.rw2`), Adobe DNG (`.dng`)

■ RAW+JPG 自動ペア判定ルール
  - 同一フォルダ内から読み込まれたファイルにおいて、拡張子を除いた基本ファイル名（baseName）が完全一致するものは、1つの写真グループとして結合処理されます。
  - 例: `IMG_1001.JPG` と `IMG_1001.CR2` は同一グループと見なされ、両ファイルに同一の基本リネーム名（例: `A遺跡_TR1_D4_20260826_001.jpg` および `.cr2`）が適用されます。

7. 出力・解析結果の見方（Output）
----------------------------------------------------------------------
■ 出力ファイル構造
  - 形式: ZIPアーカイブ形式（`.zip`）
  - デフォルトファイル名命名例: `Photos_Export_[タイムスタンプ].zip`

■ アーカイブ内ファイル構成
  - 選択・設定した命名ルールに基づき、元の高解像度データ・RAWデータがオリジナル画質のまま保持されて展開されます。
  - 命名例:
    * `A遺跡_TR1_D4_20260826_001.jpg`
    * `A遺跡_TR1_D4_20260826_001.cr2`
    * `A遺跡_TR1_D4_20260826_002.jpg` ...

8. トラブルシューティング・留意点（Troubleshooting & Notes）
----------------------------------------------------------------------
■ エラー時の対処法
  Q1. 写真をドロップしても追加されない / 「データベースが未初期化です」と表示される
    → 原因: 一部ブラウザのセキュリティ制限（プライベートモードや制限されたローカルファイル実行制限）により IndexedDB がブロックされている可能性があります。
    → 対処法: 通常のブラウザウィンドウで開き直すか、ローカルWebサーバー（例: Pythonの `http.server` や Live Server）経由で実行してください。

  Q2. 大量のRAWファイルを処理しようとするとブラウザが遅くなる
    → 原因: 数ギガバイトを超える超大量のRAWデータをブラウザメモリに保持したことによるメモリ不足（RAM圧迫）。
    → 対処法: 100枚〜300枚程度を目安に分割して登録・ZIP出力・「すべて削除」を実行してください。

■ データの取り扱い・セキュリティ上の注意
  - 本ツールで処理される写真データ・メタデータは、外部サーバーやネットワークへ一切送信されません。すべてお使いのPC端末のブラウザ内（IndexedDB）でのみ保持されます。
  - ブラウザの「閲覧履歴やキャッシュの消去」を実行すると、DB内に一時保存されたデータがクリアされる場合があります。必要な作業成果物は必ずZIPファイルとしてエクスポート・保存してください。
